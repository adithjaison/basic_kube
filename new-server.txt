  The everyday cycle (this is what you'll do 100 times)

  Memorize this loop:

  # ─── Down ─────────────────────────────────────────────────────────────
  kubectl delete -f k8s/

  # ─── (Optional) Rebuild your image if code changed ────────────────────
  cd ~/Projects/active/basic_kube/docker
  docker compose -f docker-compose.yml -f docker-compose-prod.yml build
  kind load docker-image docker-basic_kube:latest --name learn
  cd ~/Projects/active/basic_kube

  # ─── Up ───────────────────────────────────────────────────────────────
  kubectl apply -f k8s/
  kubectl rollout status deploy/hello-grpc

  # ─── Verify ───────────────────────────────────────────────────────────
  kubectl get pods,svc

  # ─── Serve (port-forward in this terminal, leave it running) ──────────
  kubectl port-forward svc/hello-grpc 8080:80

  # ─── In ANOTHER terminal ──────────────────────────────────────────────
  curl http://localhost:8080/

  That's it. Your day-to-day cycle.

  Important details

  - kubectl apply -f k8s/ applies every YAML in the k8s/ directory in alphabetical order. That's why I named files 01-, 02-, 03-… — the numbers force the order
  (Namespace before Deployment before Service, etc.).
  - kubectl delete -f k8s/ deletes them in the same order. (Order matters less for delete because everything goes regardless.)
  - kubectl rollout status blocks until the new Pods are healthy. Good "wait for it" command.
  - kubectl port-forward is blocking — that terminal stays busy. Open a second terminal for curl.

  If you only want to restart Pods without changing anything

  When you change a ConfigMap, Secret, or image but the Deployment YAML didn't change, K8s doesn't know to restart Pods. Two ways to force it:

  # Cleanest: trigger a rolling restart
  kubectl rollout restart deploy/hello-grpc

  # OR delete the Pods (ReplicaSet recreates them)
  kubectl delete pod -l app.kubernetes.io/name=hello-grpc

  Use rollout restart 99% of the time — it does a proper rolling update (no downtime). delete pod is more abrupt (all Pods die at once, then come back).

  The "stop the cluster but keep it for later" trick

  kind clusters run inside Docker containers. To pause without deleting:

  # Stop the cluster (everything in it pauses)
  docker stop learn-control-plane learn-worker

  # Resume it later
  docker start learn-control-plane learn-worker

  Your manifests, images, etcd state — all preserved. Way faster than recreating.
